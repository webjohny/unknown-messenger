# Messenger — WebRTC + AI Transcription

Monorepo: real-time text chat, video calls/streams over the LiveKit SFU,
and live AI captions generated by a separate Go microservice.

## Structure

```
apps/
  web/               Vite + React 18 SPA (TS, CSS modules, LiveKit React SDK)
  api-core/          Nest.js — Auth, REST, Socket.io Gateway, LiveKit tokens (TypeORM)
  media-ai-service/  Go — LiveKit bot, STT pipeline, Redis Pub/Sub
infra/
  livekit/           LiveKit SFU config
docker-compose.yml   Postgres, Redis, LiveKit, Coturn, MinIO
```

## Data flow

1. The client logs in to `api-core` and receives a JWT (access + rotating refresh).
2. Text: Socket.io namespace `/ws` with a Redis adapter → PostgreSQL.
3. Call: `POST /api/rooms/join` → `api-core` verifies membership, creates a
   `CallSession` and issues a LiveKit room token → the client goes straight to the SFU.
4. If `enableTranscription: true`, `api-core` publishes a command to the Redis channel
   `media:control` along with a short-lived bot token.
5. The Go service joins the room as a hidden participant, packs the incoming Opus
   RTP into Ogg, streams it to STT and publishes captions to a LiveKit DataChannel
   (topic `captions`) — latency does not depend on the backend.
6. After the call ends, the Go service publishes the full transcript to `transcripts:final`;
   `api-core` stores the segments in PostgreSQL and notifies the room over WS.

## Running

```bash
cp .env.example .env          # fill in the secrets

# 1. infrastructure
docker compose up -d postgres redis livekit minio coturn

# 2. database (first run — DB_SYNCHRONIZE=true or generate a migration)
cd apps/api-core && pnpm install
pnpm migration:generate && pnpm migration:run

# 3. services
pnpm dev:api                  # http://localhost:4000/api
pnpm dev:web                  # http://localhost:3000
cd apps/media-ai-service && go mod tidy && go run ./cmd/bot
```

`STT_PROVIDER=mock` (the default) produces synthetic captions without an external
STT account. `STT_PROVIDER=deepgram` enables real streaming to Deepgram.

Without a microphone, the transcription pipeline can be tested with a synthetic audio track:

```bash
# ROOM_TOKEN — token from POST /api/rooms/join
LIVEKIT_URL=ws://localhost:7880 ROOM_TOKEN=<jwt> go run ./cmd/testpublisher
```

## Themes (skins)

Skins live in `apps/web/themes/*.json` — one file per theme. The format and the full
list of tokens are described in `apps/web/themes/README.md`.

- UI colors are defined only through tokens (`bg-surface`, `text-ink`, `bg-bubble-own`,
  etc.) — no component hardcodes the palette.
- The theme choice is stored in `localStorage` and applied by an inline script before
  the first render, so there is no flash of the wrong theme on load.
- The switcher is the palette icon in the chat list header and on the login screen.
- A partial skin is valid: missing tokens fall back to the default theme, and a
  broken file is skipped with a `[themes] ...` warning in the server console.

## API (in brief)

| Method | Path                              | Description                   |
| ------ | --------------------------------- | ----------------------------- |
| POST   | `/api/auth/register` \| `/login`  | issues a token pair           |
| POST   | `/api/auth/refresh`               | refresh token rotation        |
| GET    | `/api/users/search?q=`            | people search                 |
| GET    | `/api/rooms`                      | the user's rooms (excluding ANON) |
| GET    | `/api/rooms/anon`                 | rooms behind anonymous links  |
| POST   | `/api/rooms/direct`               | open a 1:1 chat (idempotent)  |
| POST   | `/api/invites`                    | **no auth** — new anonymous room + link |
| GET    | `/api/invites/:token`             | public link preview           |
| POST   | `/api/invites/:token/accept`      | **no auth** — join via link   |
| GET    | `/api/rooms/:id/messages`         | history (keyset pagination)   |
| POST   | `/api/rooms/join`                 | LiveKit token + CallSession   |
| POST   | `/api/rooms/:name/end`            | end the call, remove the bot  |
| GET    | `/api/transcripts/room/:roomId`   | transcription history         |

WS events: `message:send` / `message:new`, `presence:typing`, `presence:update`,
`room:created`, `call:transcript-saved`.

Registration, people search and starting a conversation are fully in the UI (`/`).

### Anonymous links

The "anonymous link" button is present in every skin — on the login screen and in the
chat list. It creates a `RoomType.ANON` room and a `/invite/:token` link to it.

- A link can be created **without an account**: the server issues a `userNNNN` guest
  with a `null` email and no password, together with a token pair — there is no other
  way back into that account.
- Anyone following the link who is already authenticated stays under their own name;
  everyone else becomes a guest at the moment they follow it.
- An ANON room **does not appear in anyone's chat list**. The link is its only
  address, which is why the link itself is posted into the thread as a system message.
- Guests are not visible in people search.

## Security notes

- Refresh tokens are stored only as argon2 hashes and are rotated on every use.
- LiveKit tokens are issued exclusively by `api-core` after a membership check; TTL is 2 h
  for users, 6 h for the bot (`hidden: true`, `canPublish: false`).
- `DB_SYNCHRONIZE` is for local bootstrap only; production runs migrations.
