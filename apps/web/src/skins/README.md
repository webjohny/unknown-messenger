# Скіни

Скін — це **весь інтерфейс месенджера**, а не палітра. Ядро (`src/core`) не має
жодного вигляду: воно віддає дані й дії, а скін сам вирішує, з чого складається
екран, як він поділений, якими шрифтами, кольорами й формами намальований.

Ззовні на вигляд скіна вплинути не можна: скіну не передають ні `className`, ні
`style`, ні токени теми. Стилі кожного скіна лежать у власному CSS-модулі, тож
вони не перетинаються між скінами.

## Рушій

```
<SkinEngine view={{ name: 'room', roomId }} />   // id береться з поточного вибору
<SkinEngine view={{ name: 'auth' }} skinId="brutal" />  // або явно
```

`SkinEngine` отримує параметри (`view`) та ідентифікатор скіна й монтує
відповідний компонент — `<BrutalSkin view={…} />`. Невідомий id не ламає
застосунок: `resolveSkinId()` тихо повертає `DEFAULT_SKIN_ID`.

Вибір зберігається в cookie `messenger.skin`, тому сервер рендерить той самий
скін, що й браузер. `useSkinEngine()` дає скіну список усіх скінів, поточний id
і `apply(id)` — кожен скін малює свій перемикач у власному стилі (меню, діалог
по F2, неонова кнопка тощо).

## Структура скіна (однакова для всіх)

```
src/skins/<id>/
  index.tsx            маніфест + <XSkin view={…} /> — точка входу
  <id>.module.css      усі стилі скіна
  …                    решта — на розсуд скіна: parts/, окремі екрани, свої хуки
```

`index.tsx` експортує рівно дві речі:

```ts
export const <id>Manifest: SkinManifest = {
  id, label, description,
  scheme: 'light' | 'dark',
  preview: ['#…', '#…', '#…'],   // три кольори для перемикача
};

export function <X>Skin({ view }: SkinProps) { … }
```

`view` — єдиний вхід: `{ name: 'auth' }`, `{ name: 'home' }` або
`{ name: 'room', roomId }`. Як з цього зробити екран — справа скіна.

## Дані та дії (усе з `@/core`)

| Хук | Дає |
| --- | --- |
| `useSessionController()` | `ready`, `signedIn`, `user`, `logout` |
| `useAuthController()` | режим, поля, `submit`, `pending`, `error` |
| `useChatListController()` | пошук, `chats`, `people`, стани завантаження |
| `useRoomController(roomId)` | заголовок, повідомлення (`own`, `time`), набір тексту, чернетка, дзвінок |
| `useCallController(roomId)` + `CallRoot` | під’єднання до кімнати |
| `useCallStage()`, `useCallControls()`, `useCaptionFeed()` | плитки, мікрофон/камера, субтитри |
| `useCallExpansion()` + `CallOverlay` | розгортання дзвінка поверх сторінки |

Жоден із них нічого не малює. `CallRoot` і `CallOverlay` приймають `className` —
це єдиний виняток, і він потрібен, щоб скін міг оформити власний контейнер
дзвінка.

### Дзвінок поверх чату

Плитка з вебкамерою отримує `{...tileProps}` з `useCallExpansion()`. Клік по ній
відкриває `CallOverlay` — портал у `document.body` (Escape і клік по підкладці
закривають). Усередині скін малює ті самі плитки стовпчиком, а кнопки — по
центру, на стику між ними. Класи однакові в усіх скінах: `.expanded`,
`.expandedStack`, `.expandedTile` (через `composes: tile`), `.expandedBar`.

### Оголошення про дзвінок

`useRoomController` сам пише в чат `SYSTEM`-повідомлення, коли дзвінок
починається й коли завершується, і повертає їх у `message.call`
(`kind`, `text`, `duration`, `hint`, `live`). Скін малює такий запис не
бульбашкою, а рядком `.callNotice` — жирним, з іконкою; поки `live`, поруч стоїть
кнопка `room.joinCall()`.

## Власні шрифти

Більшість скінів називає шрифт і покладається на системний запасний варіант.
Якщо вигляд тримається саме на шрифті (як рукописний почерк у
`hunters-journal`), файли кладуть у `public/fonts/<id>/`, а `@font-face`
оголошують у CSS-модулі скіна. Дві умови:

- **Ім’я родини має бути унікальним** (`HJCaveat`, а не `Caveat`): імена в
  `@font-face` глобальні навіть усередині CSS-модуля, тож інакше один скін
  перевизначить шрифт іншому.
- **Зберігати `unicode-range` підмножин.** Тоді браузер тягне лише потрібні
  файли, а гліфи, яких у шрифті немає (кирилиця в латинському Cinzel),
  спокійно падають на наступний шрифт у стеку.

## Мобільна версія

Телефон — це не вужча версія того самого екрана. Робочий підхід, спільний для
адаптованих скінів:

- **Один екран за раз.** `view.name` уже каже, список це чи розмова, тож
  контейнер отримує клас (`bodyRoom`/`bodyList`, `deskRoom`/`deskList`,
  `bookRoom`/`bookList`), а друга панель ховається. Ніякого нового стану.
- `100dvh` замість `100vh` і `env(safe-area-inset-*)` у композері та нижніх
  панелях.
- **Поля вводу ≥16px** — менший розмір змушує iOS зумити сторінку на фокусі.
- Цілі ≥44px під `@media (pointer: coarse)`.
- Декор, розрахований на 1440px (нахили, плями, криві-звʼязки), на телефоні
  вимикають: він зʼїдає ширину й читабельність.

## Додати новий скін

1. Створити теку `src/skins/<id>/` за структурою вище.
2. Дописати запис у `SKINS` у `src/skin-engine/registry.ts`.

Більше нічого: перемикачі в усіх скінах читають список із рушія, тож новий скін
з’явиться в них автоматично.

## Пастки, на які вже наступили

- **Контекст накладання.** `transform`, `filter` чи `backdrop-filter` на панелі
  створюють новий контекст, і випадне меню ховається під сусідні панелі. Панель
  із меню має отримати свій `position: relative; z-index`.
- **Декор, що виходить за межі кореня**, робить корінь прокручуваним: будь-який
  `scrollIntoView` зсуває весь UI. Такий декор треба класти в шар `inset: 0`
  з `overflow: hidden`.
- **Константи для сервера** не можна експортувати з `'use client'`-модуля —
  на сервері прийде проксі, а не значення (див. `skin-engine/cookie.ts`).
- **`overflow-y: auto` вмикає і горизонтальну прокрутку.** Якщо друга вісь
  лишилась `visible`, вона обчислюється в `auto` — і будь-яка обведена рамка,
  що виступає на кілька пікселів, робить список прокручуваним убік. Пишіть
  `overflow-x: hidden` явно.
- **Спливне меню всередині анімованого контейнера.** `animation`, що рухає
  `transform`, — це теж контекст накладання. Кнопки з меню (перемикач скінів)
  тримають поза таким контейнером.
